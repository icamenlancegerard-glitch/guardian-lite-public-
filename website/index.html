01 / THE PROBLEM

A decision is not
an enforcement boundary.

AI agents can initiate consequential operations through tools, APIs, and workflows. The hard question is not only whether a request receives approval. It is whether every route to the protected service is actually controlled.

01
≠

Intent is not permission

A model-generated request does not establish user intent, authority, or safety.

02
⌁

Approval is not execution control

A decision point that can be skipped is advisory. The protected action must remain behind the guarded path.

03
≋

A record is not a guarantee

An audit record helps with review, but does not automatically prove completeness, integrity, or tamper resistance.

02 / THE APPROACH

Put the check
where actions happen.

Guardian Lite explores a control point between an AI agent and a protected service. The agent is treated as an untrusted request initiator; the protected service remains responsible for its own authentication and authorization.

05 / BOUNDARIES

Clear claims.
Clear limits.

Is Guardian Lite production-ready?

No. It is an early-stage project. A production deployment, independent security assessment, and certification have not been established.

Does it guarantee that an AI agent cannot bypass controls?

No. The M0 direct-access result applies to one configured test path. Every relevant execution path must be identified and tested in each integration.

Is this a live interactive demo?

No. This website is a static overview of the project and its documented evidence. The public repository contains documentation only; the implementation and detailed internal test materials are maintained separately.

What is M1-A?

M1-A is limited to credential-exposure attack-evidence work. Its current scope is evidence-only, and no completed M1-A result is claimed here.
